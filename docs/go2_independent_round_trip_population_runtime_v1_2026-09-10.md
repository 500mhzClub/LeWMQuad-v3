# Independent population process lifecycle V1

This library supplies the serial worker and parent lifecycle for the existing
fixed 32-case roster. It has no command-line entry point or final policy/input
admission. No independent-layout scene is launched during source preparation.

The final launcher must freeze its execution protocol and its top-level
`verify_launch(launch, full=False)` function in the source manifest. The runtime
authenticates that exact verifier source and requires it to reject missing or
changed original input, completed native queue and final policy-review evidence.
Launch flags are consistency checks, not substitutes for that verification.
The callback cannot return an alternate launch or mutate the original. The
runtime uses fixed original collector, auditor, factory and roster imports;
there is no callback for substituting a controller, model, collector or auditor.
Assertions must remain enabled, the three BLAS thread environment variables
must equal one, and the Python hash seed must equal zero.

The parent requires a fresh launch-only attempt. Before each case it verifies
the launch, measures resources for the entire remaining ordered population and
checks the existing native-process guard. It submits exactly one case to a
spawned process with a one-task limit and waits for that process pool to close
before authenticating its files and advancing. No observation timeout triggers
a restart. The 15-second wait is a resource-monitor interval, not a job deadline.
One native scene is used; the process scan is not a universal interprocess lock.

Each worker fixes OpenCV/Torch thread counts and deterministic Torch behavior,
verifies the admitted launch and completed fixed startup reference before
consuming a new-layout observation, invokes the original collection, binds all
persisted collection artifacts, and invokes the original raw sensor/controller/
physics auditor. The collector and auditor create their own fresh controllers,
models and articulated geometry. It rechecks the launch, closes the log, then
uses the previously verified case-evidence library to write a completed worker.
A separate execution receipt binds the original pre-audit collection map,
worker PID/creation time, log and terminal hash. The parent checks these against
the actual files and refuses process-identity reuse across cases.

Scientific failures with complete original audits remain in the population.
Infrastructure errors preserve raw artifacts, available collection/audit output,
the closed log and a worker failure receipt. The parent retains its exact
completed prefix and stops. Existing files cannot be overwritten or repaired.
A failure receipt vetoes a completed-case claim even if a terminal file had
already been written before a later persistence error. Unexpected process death
is retained in the parent failure record; no replacement process is launched.

The parent writes each exact completion receipt before advancing. After all
32 cases, it authenticates the full saved population, reruns full final launch
admission, rechecks all original artifact identities and writes the complete
result exclusively. Qualification and goal-achievement flags remain false.
Resource admission is not an operating-system memory limit or disk reservation.

Still required before any execution: inspect the completed original six-case
batch and all queued frontier/hold/contact outcomes, settle the final policy,
complete its prospective protocol and evidence review, implement and freeze the
final input/queue/policy verifier and launcher, and recheck actual resources.
If that policy changes the currently fixed controller/factory assignments, use
a new prospective version rather than altering these frozen sources. This
preparation supplies no new navigation, real-time or hardware evidence.
