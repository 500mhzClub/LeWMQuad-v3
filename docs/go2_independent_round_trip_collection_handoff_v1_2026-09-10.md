# Finished collection handoff for a future separate audit process

Bind the complete collector artifact roster and its closed log before the
collector exits. Record the actual publishing process identity, same boot,
original launch/source identity and exact completed within-layout reference.
Preserve partial/early-stop collection results as collected evidence. A handoff
is explicitly pending raw audit and cannot count as a completed audited episode.

The consumer must authenticate that exact handoff and original process identity,
reject a live or reused PID, reject any collection failure record, and recheck
the complete data/log roster and reference worker. A changed, omitted or added
artifact cannot be hidden by modifying receipt metadata. Neither publishing
nor reading the handoff starts a process, model, renderer or simulator scene.

Use the existing full launch-verifier interface. The helper requires its source,
test and protocol bindings in the final launch, but cannot supply the missing
final input, extended-queue and policy review. The existing runtime and current
experiments are unchanged.

An ended process and intact data do not establish a normal worker exit. A future
coordinator must separately check its own collection process handle, zero exit,
expected case/order and returned handoff SHA before scheduling the audit. It
must retain any active collection if another audit fails, preserve all failures,
and never substitute a new attempt. The helper deliberately returns no audit
execution permission and no parent-verified exit claim.

The separate audit worker, parent lifecycle checks, bounded coordinator, CPU-only
audit execution assessment and role-aware native-idle admission are still
required. Do not exclude arbitrary spawn workers from the current native guard.
Prove and measure any overlap prospectively; the completed serial timing split
does not establish an actual parallel speedup.
