# Independent population case evidence V1

This library connects the existing collector artifact roster, original raw
auditor outputs, matched startup reader and complete population readout. It has
no execution entry point and constructs no scene, model or process. It neither
changes the fixed four-arm policy nor admits a final population launch.

The future worker must bind the complete persisted collection before invoking
the original raw auditor. After that auditor returns and the worker log closes,
`persist_audited_case` authenticates the pre-audit bytes and original launch,
reads the complete physics-contact array, executes the existing matched startup
reader, reconstructs the compact readout and validates the complete case. It
writes audit/startup/readout files exclusively, rechecks the original bytes,
and only then writes the worker terminal. An infrastructure failure retains
existing artifacts and cannot be repaired or overwritten through this helper.
The future worker still must catch and record failures outside this function.

The fixed first case of each layout is always its startup reference. Every
later arm supplies that completed worker's exact hash; the reference evidence
is authenticated. A short audited acquisition/physical stop retains the
existing unavailable-startup status. No replacement reference is selected.

`read_audited_case` verifies the exact caller-bound worker and launch hashes,
the complete collector roster, closed log and every persisted audit/startup/
readout file. It checks cross-file identities, assigned treatment, the joint
success conditions and reconstructed contact/timing readout. These are saved
evidence checks, not another raw sensor or neural replay. Receipt flags alone
never grant the final launcher permission to skip the original raw auditor.

`complete_saved_population` requires the entire original ordered 32-worker
roster, verifies common reference identities, authenticates all case artifacts,
and invokes the existing eight-unit paired readout. All scientific failures
remain in all denominators. It returns evidence to the parent; it does not
publish a population result or claim qualification.

Remaining launcher work includes full original input and final policy review,
prospective source/protocol freezing, exact native queue admission, one fresh
process per case, one native scene, whole-remaining-population resource checks,
collection and original raw audit invocation, worker failure handling, parent
completion receipts and final source/input/artifact revalidation. The queued
development outcomes must be reviewed before consuming any new-layout sensor
data. Realistic timing and bounded hardware evidence remain open.
