# Prospective tracking-recovery native-prefix checks

Prepare the evidence comparison needed for one future fresh no-RGB JEPA maze-02
episode with DirectFlowResidualAnchoredController. This module has no launcher
and performs no collection. Actual native execution remains conditional on a
completed positive full-controller prefix, complete model/input admission,
resource checks, and completion of the existing six-case/frontier/hold/contact
native queue. No completed positive full-controller result is assumed here.

Admit only the fixed 860-observation controller prefix ending at frame 859,
859 complete unchanged preceding decisions and 856 compared original forecasts.
Require the assigned model state, preserved original failure, unchanged weights,
complete recorded command endpoints and the recovered full-controller boundary.
Reconstruct every saved comparison using the original decisions, independently
completed observer prefix, and original command tape. Reconstruct all public
packet fingerprints using the precise ordering used by the full replay. Check
the exact result/source/launch/artifact bindings and complete original episode
bindings. A failed or partial controller recovery cannot pass this gate.

For a fresh native episode, compare every field of all 43,700 physical samples
before executing command 859, and all 860 public observations through that
decision. All 859 earlier commands must match the original, and every native
candidate decision through 859 must match the prospective full-controller
replay. Command 859 must actually complete, with exact physical endpoints.
Compare no physics after the intervention as an equality requirement. Following
navigation outcomes require the separate full raw audit and maze evaluator.

A recovered controller can select a measured hold. In that case its first
request may equal the original terminal zero, while its observer and controller
state differ. Preserve that distinction; do not label a zero request as a
movement intervention or report movement recovery. Later measured observations
still require fresh native execution.

The checker does not choose a model, change a controller, instantiate a scene,
reorder the queue, or assert navigation success. A future launcher must bind
these sources, enforce the exact input roots and case, reexecute full original
model admission, and conduct the complete native/raw sensor/model/command audit.
