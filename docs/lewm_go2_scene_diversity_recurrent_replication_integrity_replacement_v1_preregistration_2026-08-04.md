## Failure diagnosis and one infrastructure change

The failure is consistent with process-lifetime Genesis/Vulkan retention across
distinct scene geometries:

- the exact 32-scene train half completed below the unchanged ceiling;
- the breach occurred while starting distinct scene 34, which was not a
  geometry-size outlier;
- the collection path has no per-scene or process-global Genesis destruction;
- selected-device use returned to `2,058,838,016` bytes after process exit;
- the prior 32-geometry bounded collection peaked at `15,191,449,600` bytes.

The only intervention is therefore a predeclared process-lifetime boundary:

1. a fresh parent reserves a new absent attempt and collection root;
2. one clean worker generates exactly the 32 train scenes / 128 train states;
3. that whole process exits, and a bound release barrier must observe device
   use return to no more than the pre-train baseline plus `536,870,912` bytes

4. a second clean worker generates exactly the 32 evaluation scenes / 128
   evaluation states;

There is no adaptive split, per-family choice, cap increase, subset path,
screening, refill, or fallback. Failure of either worker, the release barrier,
or the metadata-only join consumes the replacement and emits no physics result.
