## Why a replacement is scientifically admissible

The original V1 attempt terminated with
`CONSUMED_TERMINAL_INFRASTRUCTURE_FAILURE` because the evaluation path called
an older task/action-only helper whose hard-coded readout identity and expected
evaluation regret were frozen under an earlier numerical environment. The
current training feature-plan identity is still the historical
`f6f94cf589ec44324fdefe0939aa7076e25543d984464d5b264a0b2f0ff9535b`,
but an exact refit under the authorized NumPy/BLAS environment has a different
coefficient fingerprint. Rejecting that environment-specific fingerprint
before checking behavioral parity conflicts with the V1 requirement to refit
the exact ridge on the current training role rather than load an old learned
checkpoint.

The failure occurred only after both learned arms had reached their fixed
update-800 checkpoints. The joint checkpoint proves that all four
preregistered update-400 futility conditions passed and that training continued
without intervention. Neither checkpoint can be selected, retrained, resumed,
extended, edited, or replaced. No evaluation metric was written or inspected
after the failure.

The two checkpoint traces were inspected after the failure to verify the
already-preregistered train-only continuation condition and terminal update.
That disclosed inspection is not an evaluation measurement and cannot change
the frozen checkpoints, replacement gates, or task-control correction.

The failed runner had already opened the development evaluation receipts and
context RGB and had computed unwritten learned-arm predictions before reaching
the bad task-control assertion. This replacement therefore repeats access to
an already development-exposed evaluation role and must never be described as
fresh confirmation. Repeated access does not select or alter either frozen
checkpoint, but it weakens procedural independence and must remain visible in
the result.

## The only correction

Refit the task/action-only control on the current training role exactly as
specified by V1:

1. for each state, divide each of the nine dense ranks by that state's maximum
   rank;
2. use `[goal_x_body_m, goal_y_body_m, 1]` as the only features;
3. fit nine separate action heads with the existing deterministic ridge
   implementation and `lambda = 1e-3`;
4. use the existing action-specific scorer on evaluation;
5. require the train-only assembled readout identity to equal
   `8163103162bcad02b5d06542ed6087cfe6f99bd9e9deccb81f66f051a12ebc7d`.

Perform the fit twice in the same process and require every coefficient,
intercept, per-head identity, and assembled identity to be exactly equal. Bind
the Python, NumPy, PyTorch, HIP, and live GPU environment in the replacement
authority; an environment that cannot reproduce the train-only identity fails
before evaluation access.

That identity was measured using only the training role after the V1 terminal:
one training receipt load, zero training RGB opens, zero evaluation receipt or
RGB opens. It is an integrity witness, not a performance threshold.

Do not require the older helper's readout identity
`69895316b19bc179e35fdd76905aadbd50b6ad3e22e965b662ba59672c52886a`
as a coefficient-byte witness. Retain its pre-existing evaluation regret
`0.17441406250000002` as a behavioral parity witness: the refitted current-
environment ridge must produce exactly that regret before learned-arm gates are
reported. This value predates the replacement and was not recovered from the

## Unchanged evaluation gates

The joint arm earns a separate development closed-loop experiment only if all
five V1 items pass:

1. exact provenance, 128x9 completeness, finite outputs, role/scene/artifact
   disjointness, deterministic repeat, oracle regret exactly zero, and zero
   forbidden RGB access;
2. normalized physical rank regret at most `0.13`;
3. regret at least `0.02` below the refitted task/action-only control and the
   paired bootstrap upper 95% bound for `(joint - task)` below zero;
4. regret at least `0.01` below the frozen matched physical-only arm and the
   paired bootstrap upper 95% bound for `(joint - matched)` below zero;
5. regret below random expectation.

Task/action-only, physical-only, oracle, and random reports must remain in the
result regardless of gate outcome. No post-result threshold reinterpretation,
alternate scoring rule, coefficient sweep, or rescue readout is allowed.
