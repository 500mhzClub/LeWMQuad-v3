The original six-case batch and four-stage frontier, hold, commitment-contact,
tracking queue must finish and their existing verifiers must accept their
completion records. Source preparation can proceed while their owners are live;
input admission rejects live owners before expensive verification. Admission

The launcher has an exclusive output root, one fresh spawned worker and no
retry/resume mode. It checks at least 55 GiB disk and 32 GiB available memory
before admission and again before collection, and checks competing native
runners immediately before creating its attempt. It keeps the original native
contact/speed/domain and storage stops and freezes all source and input bindings.
Physics remains paused during computation, so elapsed simulated time is not a
real-time performance claim. One OpenCV/BLAS/Torch thread is used, OpenCL is
disabled in the worker, and no hardware command is issued.

Collection is followed by the full original sensor, auxiliary sensor, model,
command, renderer, visibility and native mission audit using the extended
recording bounds. The full audit and compact physical/contact/timing readout
are written before prefix comparison. If the candidate terminates before the
old boundary, the completed raw audit is retained and the prefix is marked
incomplete. Otherwise the actual physical/public/decision prefix is compared;
earlier divergence is retained as negative evidence. Neither prefix equality
nor more time implies a successful return. Inference exceptions or integrity
failures retain all written artifacts and terminate the attempt without retry.

The parent waits for worker process shutdown, verifies the persisted worker
record, rechecks inputs and outputs, and writes a terminal result retaining the
physical success and budget-control findings separately. A strict visibility
failure or failed round trip is a scientific result, not an excuse to replace
the attempt. No independent-layout, causal JEPA/memory, deployment, real-time
or hardware qualification is granted by this development diagnostic.

CLI inputs are the exact completed adapter-batch, frontier-wait, hold-wait,
contact-wait and tracking-wait result SHA-256 values. `--source-preflight-only`
verifies source/resources without requiring completion or creating output;
`--preflight-only` performs complete input admission without creating output.
The normal mode launches exactly one new episode only after all prerequisites.
