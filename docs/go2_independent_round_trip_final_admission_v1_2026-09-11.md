# Joined final admission for the existing fixed study

The source-bound `verify_population` callback joins the prepared population
inputs, all five completed diagnostics, and a separately written final review.
It does not create that review or launch any scene. The original waiters must
have ended before expensive validation or review access. Scientific failures
are retained, including a failed return or failed longer-budget prefix check.

Bound verification runs the existing complete input and five-stage queue
verifiers, links them to the same six-case batch, reconstructs review evidence,
and checks the exact review SHA within the launch's source closure. Full mode
also reruns the original population admission and each successive three-, four-
and five-stage full queue admission and requires identical evidence. The review
includes the complete six-case development summary, first three diagnostic
collections/readouts, and the actual tracking and longer-budget worker
collections/readouts/prefix findings.

The final review must explicitly choose the existing 32-case definition and
its 3,000-tick mission budget, reproduce the full assignment manifest, bind both
admissions, and explain policy/models, budget, sensing failures, causal-comparison
scope, and timing/hardware scope. A changed policy or budget is rejected: it
requires an implemented and verified successor study. This is not a decision
to retain the existing definition. No final review exists or is manufactured
by preparing this verifier. Hash and schema checks authenticate a written
decision; they cannot certify the quality of its scientific reasoning.

The callback requires the actual monitored population entrypoint, fixed stage
limits, runtime CPU monitoring and the existing independent overlap verifier.
The actual driver's separate overlap callback remains responsible for checking
its bounded CPU proof outputs. Runtime flags alone grant no execution permission.

No existing source, policy, frozen native queue or assignment is modified.
Preparing this component consumes no new-layout sensor data and grants no
navigation, real-time, hardware, model-selection or deployment qualification.
The final launcher and actual policy review remain outstanding.
