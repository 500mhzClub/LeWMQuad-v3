## Sensor boundary, causality and unchanged model inputs

Both arms acquire a live500 Hz ideal body-origin gyro at every actual2-ms
simulation step, including any native-stop row. Conversion from instantaneous
simulator orientation/angular velocity happens solely in the virtual-sensor
adapter. The controller receives measured body rates, validity, ordered clocks
and identity—not native pose, world angular velocity, geometry or a reconstructed
future trace. No rate is interpolated from the old50 Hz observations.

The500 Hz controller receives a separate51-sample100-ms history (both interval
endpoints), with exact2-ms cadence and measurement/availability times. It checks
same-episode current RGB/body clocks, all six overlapping50 Hz measurements,
the previous packet's boundary value/validity/availability, missing samples and
reset continuity. It integrates each of50 new intervals exactly once. Unknown,
stale, rewritten or privileged inputs fail rather than being imputed.

The50 Hz arm does not use fast measurements for its decisions. The existing
RGB/body/control packet,50 Hz sensor histories, ground-feedback estimator,
floor-extension observer and all learned tensors/models remain unchanged.
Each arm sees its own actual physical trajectory after commands diverge.
All RGB and fast histories are retained, including partial off-control-clock
terminal images; padded startup histories are loggable but invalid for control.

This is an ideal sensor with no bias/noise/filtering/delay or mount uncertainty.
It does not establish actual-Go2500 Hz availability, real calibration or runtime
latency. A future hardware adapter must measure and declare those separately.
