## Correction 1: issuer-only live lease creation

`ExactObjectLeaseV2` is an opaque live handle, not a public authority
constructor. Its only valid instances are objects created and strongly retained
in the exact active `TickAdmissionReceiptV2` registry by receipt-owned specific
issuance methods. A direct constructor call must raise. An object obtained with
`object.__new__`, subclassing, attribute grafting, deserialization,
reconstruction, or a copied internal shape is absent from that registry and
must be rejected terminally before any payload is returned.

The security decision must not depend only on a secret-looking Python value.
At consumption the receipt must prove all of the following by exact object
identity against its own live registry:

- the lease object is the one registered for the requested fixed kind;
- the receipt, runtime, frame outcome, reset, session, tick, producer receipt,
  consumer, and expiry epoch are the exact registered objects/values;
- the lease has not been issued twice, consumed, expired, faulted, or removed;
  and
- the runtime still recognizes the receipt as its sole active admission.

The registry retains strong references through expiry so Python object-ID reuse
cannot satisfy the check. A forged or wrong-kind lease, foreign consumer,
cross-tick/cross-reset/cross-session lease, repeated issue, replay, or registry
mismatch seals the runtime terminally. Genuine leases and receipts remain
non-copyable, non-deep-copyable, non-serializable, non-subclassable where the
language permits, and one-consumer/one-use.

Payload return is performed by a receipt-owned consume operation after registry
validation; the lease object itself stores no caller-replaceable payload and
has no generic mint or payload setter/getter. Merely reproducing a valid kind,
hash, or object layout confers no authority.

## Correction 4: closed owner-state and final-state chain

The V2 trace uses exact `OwnerStateV2` rows and one canonical
`OwnerStateBundleV2` in the thirteen-owner order above. Each row binds owner

session, and owner-state content hash. Mapping subclasses, missing/extra rows,
wrong order, duplicate owner names/IDs, booleans-as-integers, and reconstructed
hash-only substitutes reject.

`ResetReceiptV2` commits the exact zero-revision initial bundle. For the first
tick, every pre-owner row must equal that bundle byte-for-byte. For every later
tick, every pre-owner row must equal the preceding tick's post-owner row in ID,
revision, content, reset, session, and commitment. A hash-contiguous tick chain
with a discontinuous owner chain is invalid.

Every tick carries an exact transition disposition:

- `committed` requires physical, configuration, view, all four target,
  integration, and tick-chain revisions to advance by exactly one; router,
  follower, action-journal, and claim-journal transitions must match the exact
  decision/action/claim evidence; an unchanged owner preserves both revision
  and content, while an advanced owner uses `pre + 1` and a new committed
  content hash; and no owner may jump, regress, or silently change content;
- `terminal_fault_rollback` requires every mutable controller owner except the
  tick-chain evidence owner to equal its pre-state exactly after rollback; the
  tick-chain advances once to commit the terminal fault record; any safe stop
  is broker/action evidence, not a hidden controller-owner mutation; and no
  later tick is legal.

Router advances exactly when a target route is committed. Follower advances
exactly when it consumes a completed target or exploration decision and emits
a command or typed stop. Action journal advances exactly when one requested/
executed command or typed stop event is appended. Claim journal advances
exactly when one semantic claim intent is appended. Integration advances once
for each committed nonfault tick. The explicit transition rows, tagged decision
union, action evidence, and claim evidence must agree before hashing.

`ControllerTraceV2` derives its final owner-state bundle; callers do not supply

trusted as independent caller assertions. This closes both the first-tick
zero-state gap and the unrelated-final-revisions gap.

## Correction 6: every open attempt has coherent disposition evidence

`ActualOpenLedgerV2` is an append-only chain of attempted opens, not a set of
successful open keys. Every attempt receives a row and monotonically increasing
sequence before the attempt can be forgotten. `ActualOpenLedgerRowV2` adds exact
`bytes_opened`, nullable `actual_sha256`, nullable
`duplicate_of_row_sha256`, requested-path commitment, no-follow/path-resolution
evidence commitment, and policy-decision evidence commitment. The canonical
no-follow path may be `null` only when the disposition proves that no canonical
path could legally be established. Denied rows are terminal and must be the
last row.

Disposition rules are exact:

| Disposition | Required evidence |
|---|---|
| `allowed` | canonical no-follow path; exact actor/phase/role allowlist entry; nonnull expected and actual hashes that are equal; `bytes_opened == true`; no duplicate reference; no earlier allowed row with the same open key |
| `denied_duplicate` | canonical path; `bytes_opened == false`; `actual_sha256 == null`; exact `duplicate_of_row_sha256` naming a prior `allowed` row with identical actor, phase, role, canonical path, and expected hash; no first-row or invented prior is legal |
| `denied_hash_mismatch` | canonical path; `bytes_opened == true`; nonnull unequal expected and actual hashes; no duplicate reference |
| `denied_symlink` | no-follow resolution proves a symlink before payload open; `bytes_opened == false`; actual hash null; no duplicate reference |
| `denied_escape` | path-resolution evidence proves lexical or resolved escape; no payload open; actual hash null; no duplicate reference |
| `denied_wrong_phase` | a real allowlist entry for actor/role/path exists only in a different phase; no payload open; actual hash null; no duplicate reference |
| `denied_wrong_actor` | a real allowlist entry for phase/role/path exists only for a different fixed actor; no payload open; actual hash null; no duplicate reference |
| `denied_unexpected` | no exact allowlist entry exists after all earlier checks; no payload open; actual hash null; no duplicate reference |

## Correction 7: decision and action source are one closed tagged union

V2 removes caller-selected parallel `decision_kind`, `action_source`, and loose
optional branch fields. Each tick contains exactly one exact tagged decision
object:

- `TargetDecisionEvidenceV2` contains the locked canonical color, exact current
  target route, selected path and terminal yaw, and no G4 field; its per-tick G4
  call count is zero;
- `ExplorationDecisionEvidenceV2` contains the exact registered candidate-set
  admission, baseline and learned score commitments over that same object,
  selected row/path/yaw, and no target-route field; its per-tick G4 call count
  is exactly one; or
- `FaultDecisionEvidenceV2` contains a required fault code and closed fault
  stage, plus either no completed decision or one exact nested target or
  exploration decision that had completed before the fault. It cannot carry
  loose fields from both branches, and its tick transition is
  `terminal_fault_rollback`.

The exact action object is either a follower command, a typed follower stop, or
a fault stop disposition (`issued` with its exact stop evidence or
`not_safe_to_issue` with command fields absent). `action_source` is a derived
serialized value, never an authority input:

| Exact decision/action combination | Derived `action_source` |
|---|---|
| target + follower command | `target_router` |
| exploration + follower command | `learned_g4` |
| target or exploration + typed follower stop | `stop` |
| any fault decision + exact fault-stop disposition | `fault` |

All other combinations are structurally invalid. In particular, exploration
can never serialize `target_router`, target can never serialize `learned_g4`, a
normal decision cannot use `fault`, and a fault cannot retain a normal action
source. Command-source commitment, follower evidence, stall/fault state,
selected path/yaw, G4 fields, target route, and optional claim must match the
same tagged branch. A semantic claim is legal only on a nonfault target branch
for its locked color with the exact readiness and claim-journal transition; it
is absent on exploration and fault branches. Action-source counts in the final
trace are computed from these derived rows.
