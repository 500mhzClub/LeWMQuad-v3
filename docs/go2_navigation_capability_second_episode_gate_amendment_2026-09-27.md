# C1 second-episode check before the oracle gate

Approved by Andrew Knowles on 27 September 2026. This amends the navigation capability brief's gate sequence. It does not alter the currently running V2 first-episode screen, its assignments, code, frozen configuration or acceptance criteria.

1. Continue screening the ten first development episodes until C1 first completes at least 9/10, under the unchanged safety requirements.
2. Before any C0 gate run, run that same frozen harness and C1 on the ten second development episodes, in maze-ID order: 00/1 through 09/1. Require at least 9/10 round trips, with the unchanged safety requirements. This is a separate development cohort, not validation and not another harness version.
3. Only after both cohorts pass may the C0 gate start. Both C1 result sets must bind to the same harness identity. The C0 gate remains at least 19/20 with zero disallowed contacts and zero hard-criterion violations; first corrected C0 full-frame recording and strict replay remain mandatory.
4. If the second-episode check does not pass, preserve and diagnose its failures like other screen failures. All subsequent harness versions screen all 20 development episodes, in maze-ID / episode order, and require at least 18/20 before C0. This is an aggregate threshold, not a continuing 9/10 requirement on each half. The expanded screen remains in force thereafter.
5. No retries, substitutions, budget increase or extra harness versions are authorised by this addition. The six-version limit, 480-second mission budget, 160-hour programme cap, storage reserves and existing safety disqualification rules remain unchanged.

## Execution binding

The running V2 screen stops at its own cohort result; it does not automatically launch C0. Its original frozen gate entry point predates this amendment and must not be used to bypass the second-episode requirement. Before the first affected cohort, freeze its assignments and an updated orchestration configuration enforcing this amendment, without changing the controller harness. Re-project time and storage before that cohort and after it, using measured per-mission costs and the existing 15% contingency.

The second-episode check is pending, not launched. No completed mission is repeated. If it fails, the next version's all-20 screen is a new version's prescribed cohort, not a retry of this version.

## Incremental budget estimate

The completed V1 C1 screen measured 692.293 s per mission plus 226.440 s per native reader. Ten additional C1 missions therefore add approximately **2.93 wall-hours including the 15% contingency**. Applied to the previous 94.64-hour projection, this gives **97.58 hours before subsequently elapsed programme time**. This is a provisional estimate, not cohort admission: second-episode durations are not yet measured, and current resources must be checked before launch. Additional storage must be projected with all ten episodes at the full 480-second cap, using the existing hash-only retention rates.
