## Pre-reservation GPU visibility contract

The GPU visibility preflight is an authority-free diagnostic. “Authority-free”
means it cannot reserve or consume a scientific attempt and cannot grant data,
training, checkpoint, metric, later-rung, or downstream access. Operating-system
permission to enumerate the device is still required and must be explicitly
approved by the user.

The diagnostic must run as a standalone process before the exact V15 launcher
can reserve an attempt. The diagnostic invocation itself requires explicit
user-approved, out-of-sandbox/device-enabled access; setting
`HIP_VISIBLE_DEVICES=0` merely masks logical visibility and does not supply
device-node access. It must:

1. set `HIP_VISIBLE_DEVICES=0` exactly;
2. leave `CUDA_VISIBLE_DEVICES` and `ROCR_VISIBLE_DEVICES` unset, remove
   `HSA_OVERRIDE_GFX_VERSION`, and reject any conflicting accelerator selector;
3. set `OMP_NUM_THREADS`, `MKL_NUM_THREADS`, `OPENBLAS_NUM_THREADS`,
   `NUMEXPR_NUM_THREADS`, `VECLIB_MAXIMUM_THREADS`, and `BLIS_NUM_THREADS` to
   the string `1`, and observe PyTorch intra-op and inter-op thread counts of
   one before accelerator enumeration;
4. perform only runtime import/initialization and read-only enumeration, with
   no tensor allocation, kernel launch, model construction, optimizer
   construction, RGB decode, or training operation;
5. establish that accelerator enumeration completed successfully,
   `torch.cuda.is_available()` is true, `torch.cuda.device_count()` equals
   exactly one, logical device zero is named exactly
   `AMD Radeon AI PRO R9700`, and no logical GPU1 or Raphael device is visible;
6. open no canonical data, RGB, subset, target partition, manifest, audit,
   checkpoint, metric, V14 output, V15 output, or other `.generated` path; and
7. create no repository or `.generated` mutation.

An implementation must not collapse all failures into a zero-device result.
It must emit exactly one of these mutually exclusive dispositions:

| Disposition | Required meaning |
|---|---|
| `pass_exactly_one_r9700` | Enumeration succeeded; exactly one visible device exists and its exact name is `AMD Radeon AI PRO R9700`. |
| `gpu_runtime_unavailable` | Import, runtime initialization, device-node permission/access, or availability failed before a trustworthy enumeration completed. This includes the managed-sandbox `/dev/kfd` or render-node failure. |
| `gpu_device_count_mismatch` | Enumeration completed successfully, but the visible count is any value other than one. A successfully enumerated count of zero belongs here, not under `gpu_runtime_unavailable`. |
| `gpu_device_identity_mismatch` | Enumeration completed with exactly one device, but its exact name is not `AMD Radeon AI PRO R9700` or it is identified as Raphael/iGPU. |
| `gpu_selector_mismatch` | The accelerator-selector environment differs from the frozen selector contract. |
| `native_thread_mismatch` | Any frozen native or PyTorch thread count differs from one. |
| `gpu_visibility_receipt_publication_failure` | All observations passed but the external canonical receipt could not be durably published. |
