## Exact five-term Camera objective and nonlinear reduction

For one real frame microbatch of exactly `B = 4`, targets and the soft raster
are derived once. These five gradient-bearing scalar terms are then computed
separately:

```text
H = hierarchical_first_hit_nll_v9
O = target_bin_offset_smooth_l1
G = ground_clear_distance_state_balanced_bce
R = derived_raster_hierarchical_bce
N = derived_raster_cell_nll_v12

frame_total_B4 = 0.25 * (H + O + G + R) + 0.25 * N
```

`ordered_first_hit_nll` is forbidden from backward loss and diagnostics. The
current and next frames must each be evaluated on their own real B4 tensors;
neither samples nor grouped-loss statistics may be concatenated across time:

```text
camera_pair_B4 = 0.5 * current_frame_total_B4
               + 0.5 * next_frame_total_B4
promoted_backward_B4 = established_jepa_total_B4 + camera_pair_B4
matched_backward_B4  = camera_pair_B4
```

The Shared V5 camera weight is exactly `1.0`. Missing classes retain the native
source-loss semantics. Synthetic padding, current/next pooling, represented-
class weighting, and raw-numerator or denominator pooling are forbidden.

Each update uses four ordered real B4 microbatches. Four complete scalar losses
must exist independently before their arithmetic reduction is interpreted:

```text
update_backward = 0.25 * (loss_B4_0 + loss_B4_1 + loss_B4_2 + loss_B4_3)
```

Four separate `loss_B4_i / 4` backward calls are equivalent and permitted.
Computing any nonlinear loss once over a synthetic B16 is forbidden. Source
proof must construct a case where the required four-scalar mean differs from
nonlinear B16 pooling and require only the former.
